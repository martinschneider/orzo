# Orzo TODO

Prioritized for three goals (see the metrics in README.md), and a fourth one, native backends
(parked: jtreg work continues later):

1. Smaller class files (1.0x javac)
2. Pass all jtreg tests (65% of the positive, 48% of the negative tests)
3. Faster compilation (1.1x javac)
4. Native backends for x86-64 and AArch64 (planned, see [NATIVE.md](NATIVE.md))
5. 128-bit numbers: `int128` and `float128` (planned, see [NUMBERS128.md](NUMBERS128.md))

Within each goal, the items are ordered by expected impact.

## 1. Class file size

About as large as javac's now (1.0x). Still:

1. **Compact stack map frames.** `StackMapTableBuilder` only writes full frames; javac mostly writes `same`, `append` and `chop` frames.
2. **Only add the constants a class uses.** `ConstantPoolProcessor` adds references to all of the class's own methods and fields, `CodeGenerator.supportPrint()` adds `System.out` to every class (34,821 constant pool entries for Orzo's sources vs. javac's 29,960).

## 2. jtreg

Failures of the last run of `compliance/jtreg.sh`, by cause (number of tests):

1. **Nested classes**: assignments to `Outer.this.field`, anonymous subclasses of inner classes (`outer.new Inner() { ... }`)
2. **Method references**: `super::m`
3. **Semantic checks**: invalid programs that compile (403 in the last run, growing as more programs parse), e.g. incompatible types (35), ambiguous calls (30), annotation rules (about 50), overriding methods throwing more checked exceptions (4). `DefiniteAssignment` checks local variables, `ExceptionChecker` checked exceptions. `ClassChecker` checks overrides, unimplemented abstract methods, duplicate members, blank final fields, modifiers, cyclic inheritance, supertypes (final, class or interface) and file names.
4. Patterns in `switch` (`case String s ->`, `case null`), the Record and PermittedSubclasses attributes (`Class.isRecord()`, `isSealed()`), record patterns, compound assignments and increments of fields of calls (`f().i++`), selectors on array creations (`new int[2].length`)
5. Multi-dimensional arrays

## 3. Compile time

About as fast as javac now (1.1x). Profile (JFR) Orzo compiling its own sources first. Known:

1. **Type decisions**: `NumExprTypeDecider` types the same expressions repeatedly (see REVIEW.md, recommendation 1: attribution).

## 4. Native backends

An emitter of our own for x86-64 and AArch64 (Linux first, macOS later), see [NATIVE.md](NATIVE.md)
for the design. Milestones:

1. **M0**: `-target` option, attribution and IR for a subset (primitives, static methods, control flow, printing), naive x86-64 code generation, runtime entry. HelloWorld and Fibonacci run on x86-64.
2. **M1**: AArch64 (qemu in the tests), `examples/` with floating point and Orzo's own syntax.
3. **M2**: arrays (also multi-dimensional), strings and concatenation, linear scan register allocation.
4. **M3**: classes, inheritance, virtual and interface calls, casts, static initializers, enums.
5. **M4**: exceptions (a pending exception checked after calls), runtime checks.
6. **M5**: nested and anonymous classes, lambdas, boxing, generics, switch on strings and enums, records, collections in the runtime library.
7. **M6**: garbage collector, `aarch64-macos`.

Prerequisites shared with the JVM backend: the attribution pass and symbol table (REVIEW.md, recommendations 1 and 3); moving the lambda, inner class and enum desugarings out of the JVM code generator.

## 5. 128-bit numbers

`int128` (two's complement) and `float128` (IEEE 754 binary128), see [NUMBERS128.md](NUMBERS128.md).
First immutable runtime classes the operators are compiled to, later unboxed locals. Milestones:

1. `int128` runtime class (arithmetic, conversions, `toString`/`parse`), tested against `BigInteger`.
2. `int128` in the language: type, `LL` literals, promotion and casts, operators, printing, defaults, constant folding.
3. `float128` runtime class: encoding, conversions, the four basic operations, comparisons.
4. `float128` completed: `sqrt`, `fma`, `%`, correctly rounded `toString`/`parse`.
5. `float128` in the language (`Q` literals), mixed arithmetic.
6. Unboxed `int128` locals with inlined arithmetic (needs the attribution pass).
7. Lowering for the native backends.

## Other known issues

- Generics: the type arguments of own generic classes and the generic return types of own methods aren't tracked.
- Static nested classes have no `InnerClasses`/`NestHost` attributes.
- `System.out.println` is generated by a special case (`MethodCallGenerator.generate()`).

## Architecture

See REVIEW.md: the remaining expression tree migration (2), one symbol table (3). Smaller items:

- `Type` could be a plain string.
- `GlobalIdentifierMap`: merge `fieldMap`, `localMap` and `inheritedFieldNames`.
- `MethodCallGenerator`: merge `findMethodViaReflection()` and `findMethodViaReflectionTyped()`.
