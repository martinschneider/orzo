# Orzo TODO

Prioritized for three goals (see the metrics in README.md):

1. Smaller class files (1.0x javac)
2. Pass all jtreg tests (27% of the positive, 68% of the negative tests)
3. Faster compilation (2.6x javac)

Within each goal, the items are ordered by expected impact.

## 1. Class file size

About as large as javac's now (1.0x). Still:

1. **Compact stack map frames.** `StackMapTableBuilder` only writes full frames; javac mostly writes `same`, `append` and `chop` frames.
2. **Only add the constants a class uses.** `ConstantPoolProcessor` adds references to all of the class's own methods and fields, `CodeGenerator.supportPrint()` adds `System.out` to every class (34,821 constant pool entries for Orzo's sources vs. javac's 29,960).

## 2. jtreg

Failures of the last run of `compliance/jtreg.sh`, by cause (number of tests):

1. **Parser gaps** (cheap):
   - instance initializer blocks (`{ ... }` in a class body) (88)
   - type arguments, qualified names and several types in `extends`/`implements` (`extends A<Integer>`, `extends java.util.List`, `extends A, B`) (about 100)
   - modifiers in any order (`static public`) (about 60)
   - `abstract` classes and methods (31)
   - generic methods (`<T> void m()`) (23)
   - interface `default` and `static` methods (13)
   - several `for` updates (`i++, j--`)
2. **Inner, local and anonymous classes** (more than 120)
3. **Lambdas**: block bodies (`x -> { ... }`) and `void` functional interfaces (41), bound and constructor method references (`obj::m`, `Foo::new`)
4. **Semantic checks**: 266 invalid programs compile, e.g. annotation rules (90), definite assignment, overrides, enums.
5. `switch` expressions and `->` cases, `var`, records, sealed classes, `instanceof` patterns, `assert`, `synchronized`, text blocks
6. Multi-dimensional arrays, array casts (`(int[]) obj`), C-style array declarations of locals (`int a[]`)

## 3. Compile time

A profile (JFR) of Orzo compiling its own sources:

1. **Stack map frames** (61% of the samples): `StackMapTableBuilder.computeExtendedCutForSlot()` (the definite assignment analysis per slot and branch target). Use one data-flow pass.
2. **Per-class set-up** (about 10%): `MethodProcessor.getMethodMap()` collects the methods of all classes again for every class.
3. **Type decisions**: `NumExprTypeDecider` types the same expressions repeatedly (see REVIEW.md, recommendation 1: attribution).

## Other known issues

- A `null` String operand of a concatenation throws a NullPointerException (`String.concat()`).
- `finally` isn't run when `break` or `continue` leave the `try` block.
- for-each only takes the array path for a local array variable (`ForEachGenerator.isArrayIterable()`).
- Generics: the type arguments of own generic classes and the generic return types of own methods aren't tracked.
- Static nested classes have no `InnerClasses`/`NestHost` attributes.
- `System.out.println` is generated by a special case (`MethodCallGenerator.generate()`).
