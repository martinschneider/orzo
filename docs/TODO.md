## Self-Compile Workarounds (source rewritten, not the compiler fixed)

ground-rules.md says self-compile rate shouldn't drive changes to production code — the compiler should
grow to support the syntax instead. These are the exceptions, where a real fix was judged too large for
the session and orzo's own source was rewritten to avoid the limitation instead. Each links to the TODO
row describing the underlying compiler gap, so the workaround can be reverted once that's fixed.

| Priority |      Location       |                                                                                                                                                                                                                                                                                                                                                                                                                              Description                                                                                                                                                                                                                                                                                                                                                                                                                               |
|----------|---------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| M        | `LambdaParser.java` | `tryParseParams()`'s two `||`-combined conditions (`curr.next == null \|\| ...`, `!(t instanceof Identifier) \|\| ((Identifier) t).next != null`) are split into separate `if` statements with the left operand assigned to a local first, solely to unblock this file's self-compile - not because the original Java was wrong. `ExpressionParser.isCastMethodChainPattern()` only recognizes a cast/field chain when it is the very first thing in the expression (index 0), so as the right-hand side of `||` it was never recognized at all (see the `ExpressionParser.isCastMethodChainPattern()` row above). (The `while (true)` rewrite that used to be documented here is gone - once `MethodGenerator`/`WhileGenerator` were fixed to handle a literal-`true` condition correctly (see commit history), the file was reverted back to a real `while (true)`.) |
